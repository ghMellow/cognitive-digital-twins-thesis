Dai Transformer all'Intelligenza Emergente

Premessa

Il problema non è la tecnologia

  • Termini come LLM, Agente, RAG, MCP vengono usati come sinonimi — o come marketing
  • Il risultato è confusione, anche dove il vocabolario tecnico basterebbe
  • Obiettivo: costruire le fondamenta per valutare qualsiasi framework emerga domani

Architettura · Pre-2017

Il problema delle reti ricorrenti

  • Le RNN leggevano il testo parola per parola, comprimendo tutto in uno stato interno
  • Limite strutturale: più la frase è lunga, più il contesto iniziale svanisce — i gradienti scompaiono
  • "Il server che gestisce il cluster su cui gira l'app… è caduto" — soggetto e verbo già persi a 12 parole di distanza

Transformer · 2017

L'Attenzione è Tutto

  • Svolta: ogni token osserva tutti gli altri contemporaneamente — non in sequenza
  • Ogni token produce tre vettori — Query, Key, Value — e il modello impara quanto pesare ogni relazione
  • Parallelizzabile → GPU → dataset enormi → nascita degli LLM moderni
  • "Banco di pesci" e "conto bancario" producono embedding diversi perché il contesto cambia il significato

Large Language Models

Predire il token successivo

  • L'obiettivo di training sembra banale: predire la prossima parola
  • Il risultato è inatteso: semantica, ragionamento analogico, conoscenza enciclopedica — tutto emergente
  • Per predire correttamente il modello deve aver capito il contesto profondo — non memorizzato pattern
  • Conseguenza fondamentale: la semantica vive nello spazio vettoriale, non in regole dichiarate

Limiti Strutturali

Tre confini che non si superano da soli

  • Nessuna memoria persistente — ogni sessione ricomincia da zero
  • Nessuna azione nel mondo — produce testo, non legge file né chiama API
  • Finestra di contesto finita — 100K–200K token tipici; 1M+ solo su modelli specializzati

Questi non sono bug. Sono i confini del componente.
Gli agenti esistono per superarli.

Agenti

Un while loop con un cervello LLM

  • Un agente riceve un obiettivo, chiede all'LLM cosa fare, esegue, osserva il risultato, ripete
  • Il pattern formale si chiama ReAct — Reason + Act
  • La differenza da una singola chiamata LLM: persistenza, azione, correzione sul campo

Pattern ReAct

Il Ciclo dell'Agente

Esempio Concreto

Un Agente in Azione

Obiettivo: leggi config.json — cambia debug: false → true — salva.
  • Iterazione 1: "Non conosco il file" → invoca read_file() → riceve il contenuto JSON
  • Iterazione 2: "Vedo debug = false" → invoca write_file() → riceve conferma scrittura
  • Iterazione 3: "Verifico il salvataggio" → read_file() → debug = true → fine loop

Strumenti

Function Calling e MCP

  • L'LLM genera chiamate di funzione strutturate; il programma le intercetta ed esegue — questo è il function calling
  • Novembre 2024: Anthropic lancia Model Context Protocol (MCP) — standard aperto per esporre strumenti agli LLM
  • 2025: OpenAI e Google DeepMind lo adottano → standard de facto del settore
  • Analogia: USB-C — uno strumento scritto una volta, compatibile con qualsiasi LLM che lo supporti

Evoluzione

Da ReAct ai Modelli Ragionanti

  • ReAct (2022): il primo paradigma agentico — loop con azioni reali nell'ambiente
  • Reflexion + Tree of Thoughts (2023): il loop potenziato — memoria di errori e esplorazione parallela di percorsi
  • RL-based Reasoning (2025–2026): discontinuità epistemica — la logica di controllo passa da scritta esternamente ad appresa dal modello
  • Implicazione: il modello non esegue un loop scritto da un umano — ha appreso quando e come iterare

Prompting Strutturato

Le Skill: procedure in Markdown

  • Una skill è una procedura di prompting condensata in Markdown — non codice, solo istruzioni
  • Descrive il come affrontare un'operazione ricorrente, passo per passo, leggibile dall'uomo
  • Esempio: una skill ingest-paper.md dice all'agente come leggere un paper, aggiornare la wiki e registrare nel log
  • Valore: modificabili senza toccare codice, condivisibili, versionabili con Git

Memoria

Il problema aperto degli agenti

  • Ogni sessione LLM ricomincia da zero — non esiste stato persistente nativo
  • Per un chatbot generico è accettabile. Per una knowledge base in crescita è un problema critico
  • La difficoltà è tripla: cosa memorizzare, come organizzarlo, come recuperarlo entro la finestra di contesto

Approcci alla Memoria

RAG vs. LLM Wiki

  • RAG: indicizza documenti in un vector store → recupera chunk semanticamente simili → inietta nel contesto
  • Limite RAG: l'LLM riceve frammenti sconnessi, non sintesi — la qualità dipende dall'embedding
  • LLM Wiki: costruisci e mantieni una wiki sintetica in Markdown che l'agente aggiorna ad ogni ingestione
  • Risultato: memoria che compila, non recupera — conoscenza strutturata invece di chunk grezzi

Mercato

Il mercato impacchetta il blob

  • 2025–2026: nessuno standard consolidato — LangChain, LangGraph, CrewAI, Claude Code, smolagents coesistono

Workflow

L'idea di Andrej Karpathy: LLM Wiki

  • raw/ — documenti sorgente immutabili: paper, call, trascrizioni. Non si toccano mai.
  • wiki/ — elaborazione sintetizzata: fonti, concetti, log, scaffolding. L'agente la aggiorna.
  • CLAUDE.md — manuale operativo: ruolo, contesto, procedure, vincoli. Letto ad ogni bootstrap.
  • Bootstrap: carica CLAUDE.md → leggi wiki/index → leggi log → capisci stato → agisci
  • Obsidian: programma di frontend che permette di vedere la vista grafo delle connessioni dei documenti

Output

MARP: Wiki → Presentazione

  • MARP (Markdown Presentation Ecosystem) — trasforma Markdown in slide HTML/PDF
  • L'agente, su richiesta, estrae capitoli dalla wiki e genera un file deck.md in sintassi MARP
  • Workflow: ingest paper → wiki aggiornata → richiedi "genera slide su tema X" → output pronto per difesa
  • Valore: la conoscenza non rimane isolata nella wiki — diventa automaticamente comunicabile
  • Visualizzazione: VSCode + plugin MARP, o export a PDF via CLI

Riepilogo

Quattro cose da ricordare

  • Transformer: l'attenzione ha reso possibile la scala — da lì nascono gli LLM
  • Agente = LLM + loop: il pattern ReAct trasforma un oracolo passivo in un attore autonomo
  • Memoria: il problema aperto — la wiki Markdown è la soluzione più efficace a scala umana
  • Framework: cambiano, la struttura no — impara la struttura, i framework vengono da soli
